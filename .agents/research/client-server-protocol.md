# Client-server protocol map

One logical RPC protocol ("four-quadrant message model", `packages/host/apiproxy/src/api/rpc.ts`) runs over three physical carriers. All wire forms are JSON; correlation is an `rpcId` minted by the initiator and echoed by the responder.

**Wire full forms** (zod: `api/rpc.schema.ts`): `client-request {type,rpcId,method,payload}`, `server-response {type,rpcId,result}`, `server-request {type,rpcId,method,payload}` (server-initiated: answerable interactions + pure pushes), `client-response {type,rpcId,result}` (answers a server-request). `result = {ok:true,value} | {ok:false,error}`; `error = {code,message,details}` with a closed code union (`RpcErrorDetailsMap`, ~40 codes). Business errors always ride HTTP 200; HTTP status is carrier-only.

## Transport A — HTTP POST /api/<method> (unary RPC)
Browser `WebApiClient` and in-process clients POST a `client-request` envelope to `/api/<method>`; the response body is a `server-response` (`packages/client/connection/src/client/rpc.ts`, `packages/host/apiproxy/src/fetch/handler.ts`). `/api/respond` accepts a `client-response` and returns `RpcReceipt {accepted:true|false, reason:"not-pending"|"bad-response"}`. Carrier codes: 403 untrusted Host, 413 body too large, 415 non-JSON, 400 bad body, 404 unknown method, 426 GET on event paths. The browser-trust fence (`api-request-trust.ts`) checks the Host header against loopback + configured `trustedHosts`; a privileged set (`settings.*`, `credentials.*`, `agentPreset.read/copy/openDocument/remove`, `host.pickDirectory/openPath`, `llm.discoverModels`) is pinned to loopback.

**Method registry** (`api/rpc-map.ts`, 60 unary methods; wire paths are the keys): `session.list|search|create|history|models|selectModel|rename|fork|prompt|attachment|updateQueue|cancel`; `subagent.list|history|prompt|interrupt`; `host.describe|pickDirectory|listDirectory|createDirectory|openPath`; `workspace.list|create|rename|delete|insertBefore|insertSessionBefore|archiveSession`; `skill.list`; `agentPreset.list|select|read|copy|openDocument|remove`; `goal.create|edit|pause|resume|complete|clear`; `settings.describe|openDocument|update|replace|mutate`; `credentials.describe|set|unset`; `llm.providers|models|discoverModels`. Payload/value schemas per method in `api/*.schema.ts` (two-level parse: envelope, then business schema).

## Transport B — WebSocket downlinks (browser only)
Upgrades at `/api/events.mux` and `/api/events.host` (`packages/client/connection/src/websocket-downlink.ts`); downlink-only (client messages close 1008). Each frame is a `server-request` whose `method` equals the frame `type`. **Mux frames** (`api/events.ts`): `session/event` (raw SessionEvent + optional host-computed `view`), `session/subscribed`, `approval/requested|resolved`, `question/requested|resolved`, `session/queue` (inbox snapshot), `session/jobs`, `session/projection`, `stream/error`. **Host frames**: `host/session-added|removed|status|agent-error`, `host/workspace-changed|removed|order-changed`, `host/archived-sessions-changed`, `host/remote-event` (allowlisted cordis events verbatim), `stream/error`.

**Streaming chat tokens**: no SSE/EventSource in the browser — every `assistant/chunk` token event is pushed as a `session/event` frame over the mux WebSocket; the runtime accumulates blocks (`packages/client/runtime/src/client/sessions/partial.ts`). `ConnectionController` (`client/connection.ts`) opens both streams, performs a strict readiness handshake (`host.describe` + stream open), and reconnects with exponential backoff; on reopen the host replays baselines: `session/subscribed`, pending `approval/requested` / `question/requested` with their **stable rpcIds**, and queue/jobs snapshots.

## Transport C — in-process SSE (isomorphic, not browser-facing)
`toFetchHandler` also serves `GET /api/events.mux|host` as SSE (`data: <server-request>` frames, `fetch/handler.ts`); `InProcessApiClient` consumes it (`fetch/client.ts`). In the web deployment the connection plugin answers those GETs with 426 (WebSocket required) — SSE is for in-process/non-browser consumers.

## Typert RPC gateway (packages/api/gateway) and remotes (packages/api/remotes)
The gateway is a Cordis service (`typertGateway`) that **intercepts** `/api/<namespace>/<method>` endpoints on the shared channel before the apiproxy fallback (`gateway/src/index.ts` → `connection.rpc.intercept("/api", ...)`). Payload must be exactly `{args}`; the response is the standard result envelope (`{ok:true,value}` / `{ok:false,error}` with codes like `definition-unavailable`, `context-not-found`, `cancelled`). It resolves strict Typert descriptors or SRC markers, applies lookup/context providers, and returns `undefined` results with no `value` field. The client half (`gateway/src/client/index.ts`) mounts generated namespaces as `ctx.remote.<ns>.<method>` and forwards remote events to `ctx.remote.$on`. Remotes itself exposes no transport: `agent-lookup.ts` configures `agent`/`session` Typert lookups used by gateway endpoints, and `remote-events.ts` is the allowlist (`settings/document-updated`, `commands/change`, ...) delivered as `host/remote-event` host-stream frames.

## Web server routes (packages/bundle/web-app, host/webserver, host/frontend-static)
`webServer` (node:http) registers exact/prefix/upgrade routes, one fallback seat, and `tapIndex` transforms. Routes: **`GET|HEAD /api/health`** → `200 {ok:true}` (405 otherwise); **`POST|GET /api/shutdown`** → `202 {ok:true}` then `ctx.appExit(0)` (503 without a launcher, 405 otherwise); prefix `/api` (connection); upgrades `/api/events.mux|host`. The SPA fallback (frontend-static) serves the built `@deepseek-ai/dsh-web-frontend/dist` (403 traversal, SPA fallback to index.html, MIME by extension); index HTML passes through taps (e.g. the shutdown-on-close `beforeunload` beacon). Client JS bundles are static dist files; the app bootstraps via `window.__DSH_BOOT__` injected into index.

## Settings sync
`settingsScope` (`packages/client/ui-settings/src/client/settings-scope.ts`): each feature binds a namespace (`ctx.settingsScope.bind({namespace})`); the controller serializes reads/writes over `settings.describe` / `settings.mutate` (path ops, `expectedRevision` optimistic concurrency, `settings-conflict` error), publishes snapshot stores, and refreshes on the forwarded `settings/document-updated` remote event and `connection/reset`. Non-loopback pages degrade to `memory` persistence.

## Approvals & questions (packages/interaction)
`dsh-user-approval` emits the `approval/request` waterfall; api-proxy is the answerer: it mints a stable rpcId, records a `PendingApproval`, and pushes `approval/requested` (with `approvalId`, toolName, callId) to every mux queue. The UI answers via `POST /api/respond` with a `client-response` whose value is `{sessionId, approvalId, outcome:"allowed-once"|"rejected"}`; the proxy broadcasts `approval/resolved` and settles the pending ask. `dsh-user-questions` mirrors this: `question/requested` (rpcId = question-batch id) → respond `{sessionId, answer}` → `question/resolved`. Pending entries survive disconnects and replay on mux reopen.

## SDK (packages/sdk) — separate protocol, fully reusable
JSON-RPC 2.0 over **newline-delimited stdio** (`protocol/src/transport.ts`; server plugin `@deepseek-ai/dsh-sdk-jsonrpc-server`). Requests: `initialize {cwd,provider,model,maxTokens?}`, `session/prompt {sessionId,contentBlocks}`, `shutdown`. Notifications: `session.event`, `session.status`, `subagent.started`, `subagent.finished`. No HTTP/WS; consumed by `@deepseek-ai/dsh-sdk-client` and the Python SDK.

## Web-only vs reusable
**Web-only**: WebSocket downlinks, browser-trust/DNS-rebinding fence, privileged loopback pins, SPA static serving, `host.describe` readiness handshake, settings memory fallback.
**Reusable by any HTTP client**: the `POST /api/<method>` envelope and method registry, `/api/respond`, SSE `events.mux|host` (fetch level), all Typert gateway endpoints, the four-quadrant message model, and the entire stdio SDK protocol.
